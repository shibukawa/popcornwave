# Popcorn Web documentation site

[Astro Starlight](https://starlight.astro.build/) site published to
<https://shibukawa.github.io/popcornweb/> by
[`.github/workflows/docs.yml`](../.github/workflows/docs.yml) on every push to
`main` that touches `website/`.

## Local development

```sh
npm install
npm run dev
```

`npm run build` writes the static site to `dist/`, and `npm run preview` serves
that build with the production `base` path applied.

## Adding a page

A page becomes part of the site when its Markdown file lands in the appropriate
directory. There is no separate page registry; the directory determines the
autogenerated sidebar group.

| Directory | Sidebar group |
| --- | --- |
| `src/content/docs/start/` | Start Here |
| `src/content/docs/guides/frontend/` | Guides → For Frontend |
| `src/content/docs/guides/backend/` | Guides → As a Backend |
| `src/content/docs/guides/architecture/` | Guides → Architecture |
| `src/content/docs/guides/deployment/` | Guides → Deployment |
| `src/content/docs/productivity/` | Productivity Support |
| `src/content/docs/pw/project/` | pw command → Project |
| `src/content/docs/pw/database/` | pw command → Database |
| `src/content/docs/reference/` | Reference |
| `src/content/docs/appendix/` | Appendix |

Every page needs `title` in its frontmatter; `sidebar.order` controls position
within the group.

```markdown
---
title: Middleware
description: Composing middleware around a Popcorn Web application.
sidebar:
  order: 3
---
```

Japanese pages mirror the English tree under `src/content/docs/ja/` with the
same filenames, so `guides/frontend/middleware.md` pairs with `ja/guides/frontend/middleware.md`.
If a translation is missing, the site falls back to the English page instead of
returning a 404.

To add a new sidebar group, create the directory in both locales and add one
entry to `sidebar` in [`astro.config.mjs`](astro.config.mjs).

## Linking

Internal links use site-root paths and include the locale, but they **exclude**
the deployment base:

```markdown
[Configuration](/guides/architecture/configuration/)
[設定](/ja/guides/architecture/configuration/)
```

At build time,
[`src/plugins/satteri-base-links.mjs`](src/plugins/satteri-base-links.mjs)
adds the configured `base`. Content therefore never hard-codes
`/popcornweb/`.

The plugin cannot reach `hero.actions` because those links come from the two
`index.mdx` frontmatter blocks.
[`src/components/Hero.astro`](src/components/Hero.astro) applies the same base
logic there, keeping hero links in the same site-root form as the rest of the
content.

## LLM-facing output

[`starlight-llms-txt`](https://github.com/delucis/starlight-llms-txt) publishes
three plain-text views of the English docs for LLM and agent consumers:

- `/popcornweb/llms.txt` — index
- `/popcornweb/llms-small.txt` — abridged
- `/popcornweb/llms-full.txt` — everything

## Changing the deployed URL

`base` is declared once, at the top of [`astro.config.mjs`](astro.config.mjs).
Moving the site to a custom domain means setting `base` to `'/'` (and `site` to
the domain); no content changes are required.
