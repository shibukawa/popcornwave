プロジェクトのルートには `public/` ディレクトリがあります。そこに置いたものは配信され、
しかもバイナリの横ではなく中に入って運ばれます。デプロイするファイルはひとつだけ。
昨日のリリースのスタイルシートが残っている、ということも起きません。

```
public/
  favicon.ico
  generated/app.css
  images/logo.svg
```

```
GET /public/images/logo.svg
```

準備はこれで全部です。`pw init` がディレクトリと、それを埋め込む `public.go` を書くので、
生成直後のプロジェクトはすでにここから配信しています。

## 埋め込んでいるもの

`public.go` は生成物ではなく普通のアプリケーションコードで、読める形のままです。

```go
package publicassets

//go:embed all:public
var embeddedPublic embed.FS

func init() {
	middlewares.RegisterPublicFS(PublicFS())
}
```

`main` がアセットに一切触れないのは、この `init` での登録があるからです。フレームワークは
起動時にこのファイルシステムを受け取ってマウントします。`server.public.enabled` が有効
なのに登録されたファイルシステムが無い場合は、黙って 404 を返すディレクトリになるのでは
なく、起動エラーになります。

フレームワークが持つ静的ディレクトリの規約は `public` だけです。それ以外に配信したい
もの——ユーザーのアップロード、生成されたレポート——は普通のルートであり、置き場所として
より適しているのはたいてい[オブジェクトストレージ](/ja/guides/backend/object-storage/)です。

## ビルド時の事前圧縮

[`pw build`](/ja/pw/project/build/) は、コンパイルの前に圧縮可能なアセットそれぞれの隣に
`.zstd` の兄弟ファイルを書きます。おかげで配信時の CPU コストはゼロです。エンコード済みの
バイト列はすでに存在していて、リクエストはそれを受け取るか、元のファイルを受け取るかの
どちらかです。

対象はメディアタイプで決まり、実際に効果があるものだけが入ります。

| 圧縮する | しない |
| --- | --- |
| `.html`、`.css`、`.js`、`.mjs`、`.json`、`.map`、`.txt`、`.xml`、`.svg`、`.webmanifest`、その他の `text/*` | SVG 以外の画像、音声、動画、フォント、アーカイブ、WebAssembly——すでに圧縮されているもの |

サイドカーはビルド成果物です。生成される `.gitignore` は `public/**/*.zstd` を除外しますし、
ビルドは元ファイルが消えたサイドカーを削除するので、消したファイルの表現だけが取り残される
ことはありません。

`.zstd` のパスが URL になることは決してありません。それは隣のアセットの内部表現であり、
そこへのリクエストは 404 です。

## リクエストが受け取るもの

| 挙動 | 内容 |
| --- | --- |
| メソッド | `GET` と `HEAD`。それ以外は `Allow` 付きの `405` |
| 末尾スラッシュ無しのマウント | マウントへの `308` リダイレクト。クエリ文字列は維持 |
| エンコーディング | `Accept-Encoding` が q 値 0 超で明示的に許し、*かつ*サイドカーがある場合に `zstd`。それ以外は元のファイル |
| `Vary` | ネゴシエーションを行ったレスポンスには常に `Accept-Encoding` |
| `ETag` | strong。実際に送るバイト列から導出 |
| `If-None-Match` | 一致すれば `304` |
| 受け入れ可能な表現が無い | `406` |

ETag は表現ごとに計算されるので、同じファイルの圧縮版と非圧縮版が検証子を共有することは
ありません。片方を保存したキャッシュが、もう片方を求めたクライアントにそれを返すことは
できません。

ディレクトリは `index.html` があればそれとして解決され、無ければ `404` です。
ディレクトリ一覧は存在しません。

## パスの扱い

ここの規則はすべて拒否であり、例外が無いという意味で知っておく価値があります。

- ドットで始まるセグメントは拒否されます。`public/` 配下の `.env` や `.git/config` には
  到達できません
- トラバーサル、バックスラッシュ、NUL は、パーセントデコードを 1 回行ったあとで拒否されます
- シンボリックリンクは拒否されます。ローカルのルート自体も、その下のものも、通常ファイルで
  ないものも。`pw build` も同様に、リンクをたどってその先を埋め込むことを拒否します
- リクエストパスの `.zstd` 接尾辞はその場で拒否されます

## 開発中の挙動

[`pw dev`](/ja/pw/project/dev/) は専用のビルドモードでコンパイルし、リクエストのたびに
`public/` をディスクから直接読みます。スタイルシートを編集してリロードするだけ——事前圧縮も
リビルドも再起動もありません。このモードではエンコーディングのネゴシエーションを行わず、
サイドカーの読み書きもせず、削除したファイルはバイナリに古いコピーが埋まっていても `404`
を返します。

このモードの外では、`server.public.read_local = true` が通常のビルドで同じ「ディスク優先」の
挙動を与えます。埋め込みツリーの上にディレクトリを重ねるデプロイのためのものです。

## 設定

| キー | 既定値 | 意味 |
| --- | --- | --- |
| `server.public.enabled` | `true` | そもそも配信するか |
| `server.public.mount` | `"/public"` | マウント先 |
| `server.public.read_local` | `false` | 埋め込みツリーより `./public` を優先する |

マウントは絶対パスかつ正規形で、ルートではなく、ワイルドカードを含まないこと。ここと
衝突するアプリケーションのルートは、マウントを覆い隠すのではなく起動を失敗させます。
`enabled` を切ってもルートが登録されなくなるだけで、バイナリは何も変わりません。アセットは
埋め込まれたまま、到達できなくなるだけです。

フレームワーク自身のブラウザ向けスクリプトはここには入りません。アプリケーションの
ルーティングより手前の固定パス `/_pw/` から配信されます。だからこのエンドポイントを
どう設定しても使えなくなりません。[非同期レンダリング](/ja/advanced/async-rendering/)を
参照してください。

## レスポンス圧縮とは別物

上のサイドカーは静的なファイルで、ビルド時に一度だけ圧縮されます。アプリケーションが
たった今レンダリングした HTML レスポンスを圧縮するのは別のスイッチで、トレードオフも
別です。[レスポンス圧縮](/ja/guides/frontend/compression/)を参照してください。あちらの
ミドルウェアが、このハンドラの返したものを再圧縮することはありません。
