import { Card, CardGrid } from '@astrojs/starlight/components';

An `http.Handler` binds one request, runs application logic, and writes one
complete response using ordinary navigation and form semantics. A minimal build
stays a small, practical TinyGo target: no component graph, no patch protocol,
no hydration, no browser runtime.

<CardGrid>
  <Card title="Standard library first" icon="seti:go">
    Routing is `net/http`'s own `ServeMux` — same patterns, same wildcards, same
    precedence — and handlers are plain `http.HandlerFunc`.
  </Card>
  <Card title="Generated, not reflected" icon="setting">
    Templates, SQL, request binding, and OpenAPI are compiled into Go ahead of
    time by `pw generate`. No runtime reflection, so it runs on **TinyGo** too.
  </Card>
  <Card title="One command to a running app" icon="rocket">
    `pw init` scaffolds a complete project — handler, typed page, document
    shell, SQL, migration, error pages, Devbox — and `pw dev` watches it.
  </Card>
  <Card title="Operations included" icon="approve-check">
    Startup validation, `/healthz`, `/readyz`, `/openapi.json`, graceful
    shutdown, request IDs, access logs, and validated security headers.
  </Card>
</CardGrid>

An opt-in server-driven UI layer sits on the same `net/http` foundation. It
extends this foundation rather than replacing it, and an application never pays
for what it does not import.
