---
id: api:cli-new
type: api
title: pw new
---
pw new scaffolds one more source of a kind the project already contains, so a second handler costs a wizard rather than a copied file whose route, template, and mux registration have to be fixed by hand.

```yaml
status: not implemented
usage: "pw new [kind]"
requirement: requirement:incremental-project-capabilities
mode: decision:post-init-scaffold-wizard
inputs:
  kind: preselects the first wizard step; omitting it lists the available kinds
kinds:
  handler:
    status: the only implemented kind
    writes: an HTTP route, its handler source, and its optional typed template
  future:
    candidates: page, query, migration, template
    extension_cost: one kind entry, one step list, and its scaffold branch
handler_questions:
  package:
    default: the working directory when it lies under a data:project-config generate.handlers entry, because that is where the operator already is
    resolution:
      - the working directory itself, when it is a listed handler directory or below one
      - otherwise no preselection, and the step lists the generate.handlers entries and their existing handler packages
    reason: a directory outside the handler purpose of decision:explicit-generation-sources would produce a route nothing analyzes, so it is never offered
    html_response: the destination must also lie under a generate.templates entry, since the page template is generated by a different purpose
    outside_only: a project whose listed directories cannot take a handler stops with the keys to edit
    effect: a package that does not exist yet also gets its flow:handler-registration mux and Handlers accessor for the project.toolchain
  method: GET, POST, PUT, PATCH, or DELETE
  path: literal route path, validated as a Go 1.22 method-and-path pattern
  name:
    default: derived from method and path
    use: the source file stem and the exported handler identifier
  response:
    html: .pw.html template beside the handler, rendered through WriteHTML
    api: JSON response through WriteAPI
  request_input:
    asked_when: the method or path can carry input
    yes: a private request type and a pw.Parse call site
  review: lists every file to create and every follow-up command
outputs:
  - "{package}/{name}_handler.go with an init() route registration and a standard func(http.ResponseWriter, *http.Request)"
  - "{package}/{name}.pw.html when the response is HTML, extending the requirement:nested-html-templates document shell"
  - "{package}/index.go mux and Handlers accessor when the package is new"
  - generated {source-base}_pw_gen.go from the api:cli-generate run that follows
manual_steps:
  new_package: concept:application-entry-point owns main.go, so wiring a new handler package is printed rather than injected
rules:
  - require a data:project-config project root, found by walking up from the working directory
  - offer only destinations under a data:project-config generate.handlers entry, and under generate.templates too when the response is HTML
  - register a literal method-and-path pattern, because rule:static-route-discovery drives generated OpenAPI
  - refuse a pattern the target package already registers, naming the file that registers it
  - refuse an existing destination file; report the conflict and stop
  - write nothing when any planned file cannot be created, so no orphan handler source reaches the project
  - keep the written sources when only the api:cli-generate step fails, because the operator owns and fixes them
  - emit the mux type that project.toolchain selects, per flow:handler-registration
  - run api:cli-generate after writing, so the project stays buildable
  - never edit an existing handler source, main.go, or the document shell
relations:
  flow: flow:handler-scaffolding
  layout: concept:project-layout
  sibling: api:cli-add installs capabilities rather than sources
  generation: api:cli-generate
exit:
  success: 0
  canceled_wizard: 0 with a canceled notice and no files written
  no_terminal: nonzero with usage
  conflict_or_invalid_pattern: nonzero with the path and the reason
```
