---
id: requirement:serverless-http-hosting
type: requirement
title: Serverless HTTP Hosting
---
One Popcorn Wave application binary for either backend runs unchanged on scale-to-zero HTTP container services and HTTP-forwarding function hosts.

```yaml
runtime_contract:
  ordinary_container: data:server-runtime-config PORT
  aws_lambda_web_adapter: AWS_LWA_PORT, falling back in the adapter and application to PORT then 8080
  azure_functions_custom_handler: FUNCTIONS_CUSTOMHANDLER_PORT
resolution:
  priority:
    - FUNCTIONS_CUSTOMHANDLER_PORT
    - AWS_LWA_PORT
    - data:server-runtime-config port after PORT binding
  validation: a special assignment must be a decimal integer from 1 through 65535; invalid input refuses startup and names the variable
deployment:
  aws_lambda:
    adapter: AWS Lambda Web Adapter in an extension layer or container image
    application_change: none
    excludes: a framework-owned Lambda Runtime API client
  azure_functions:
    adapter: custom handler with HTTP request forwarding enabled
    application_change: none
    scope: HTTP trigger and output only; bindings using the custom payload need a separate adapter
  cloud_run_app_runner_container_apps:
    adapter: none; policy:container-runtime-image already satisfies the assigned-port process contract
source_function_boundary:
  vercel_go: exported Handler generated by requirement:serverless-source-entrypoints
  cloud_run_functions: Functions Framework registration generated by requirement:serverless-source-entrypoints
  distinction: both remote-build source with no application main and therefore need a generated entry point, not a listener environment alias
non_goals:
  - creating provider resources, uploading artifacts, setting domains, or storing credentials
  - non-HTTP event triggers
  - DigitalOcean/OpenWhisk event functions
  - Fastly Compute or another component-model edge-Wasm host before decision:wasi-http-deferred is reopened
acceptance:
  - an ordinary process with neither special variable keeps its configured port
  - each special variable selects its assigned port without changing application source
  - an invalid special port fails before database and telemetry initialization
  - decision:serverless-target-scope is the authoritative initial provider list
  - the deployment guide classifies shipped, committed, blocked, and deferred hosts
backend_parity:
  nethttp: pw.Run resolves the assigned listener port
  fasthttp: pwfast.Run resolves the same assigned listener port through pwconfig.HostingPort
  source_functions: requirement:serverless-source-entrypoints owns the exported net/http boundary
```
