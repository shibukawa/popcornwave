# Internationalization: message catalogs and locale routing

None of this exists until a project declares a second locale. A single-language
project writes plain text in its templates and never opens a catalog — `{t}`
means nothing special, there are no modes, no negotiation, and no `Vary`. Reach
for this when you actually have another language to ship.

Two halves: a **catalog** compiled into typed Go and checked against every
reference at build time, and a **routing mode** per path prefix that decides
which language a request is served in.

## Declaring the languages

`[i18n]` lives in `popcornweb.toml` (build configuration — the catalog is a
generation input, not a runtime setting):

```toml
[i18n]
locales = ["ja", "en"]
default_locale = "ja"
catalog = "messages"       # directory holding the YAML files
missing = "error"          # or "warn"
prefix_default = true
path_routes = ["/"]
cookie_routes = ["/admin/"]
header_routes = ["/api/"]

[i18n.label]
ja = "日本語"
en = "English"
```

An empty `locales` with any other `i18n.*` key set is a load error: nothing would
declare which languages exist. `default_locale` must be one of `locales`, and a
`label` naming a tag that is not declared is an error too.

## The catalog

One file per scope, in `messages/`:

```yaml
title:
  locales:
    ja: "お店"
    en: "Shop"

greeting:
  params: ["name string"]
  locales:
    ja: "ようこそ、{name}さん"
    en: "Welcome, {name}!"
```

`pw generate` compiles the catalog into a typed Go package and checks every
reference against it. A misspelled ID, a missing argument, or a language that
never supplied a translation stops the build. Adding a language adds no generated
code — the tables grow by a row.

## Referencing a message

```html
package pages

messages shop

export component Page(name: string): html {
<section>
  <h1>{t title}</h1>
  <p>{t greeting, name: name}</p>
  <a href="/{lang}/about">{t title}</a>
</section>
}
```

`messages shop` says which catalog file this template's references resolve
against, so `{t title}` means `shop.title`. It is one line per file, and a file
carrying a reference without it is an error — nothing is inferred from the path,
because then moving a component would silently change which text it renders. Two
templates declaring the same scope share its messages (that is how a `common`
scope for `Save` and `Cancel` works); a message from elsewhere is reached by
writing the qualified ID, `{t common.save}`.

**`{t}` and `{t x}` are different things.** `{t}` interpolates a parameter named
`t`, exactly as it always did. Only an identifier followed by another identifier
is a message reference, so a component taking `t time.Time` keeps working.

## Links and assets carry the locale explicitly

Two names are in scope in every template, and they are not interchangeable.

| Name | Value | Use |
| --- | --- | --- |
| `{lang}` | the URL segment: the tag under path routing, **empty** elsewhere | links; an empty value removes the slash before it |
| `{langtag}` | the tag itself, never empty | `lang` attributes, localized asset paths |

```html
<a href="/{lang}/about">            <!-- /ja/about, or /about where the locale is not in the path -->
<html lang="{langtag}">
<img src="/assets/{langtag}/hero.png">
<img src="/assets/logo.png">        <!-- not localized: neither name appears -->
```

The split exists because an image can be translated too. If the framework
rewrote links it would have to decide whether `/assets/hero.png` is a route or a
file, and no attribute tells it — an anchor can point at a PDF and an image
source can point at a route.

## Plurals belong to the target language

How many forms a count needs is a fact about the language, not the message.
Declare them per locale:

```yaml
item-count:
  params: ["n int"]
  plural: n
  locales:
    ja: "カートに{n}件"
    en:
      one: "{n} item in your cart"
      other: "{n} items in your cart"
```

```html
<p>{t item-count, n: count}</p>
```

A locale that omits a form its rules require fails the build. Numbers are grouped
for the locale on the way in — `1,234` in English and Japanese, `1.234` in
German.

## A sentence with a link inside it

Splitting a sentence into three messages makes it untranslatable, because word
order moves. Write it as a block and let the translation decide where the link
lands:

```html
{t agree}<a href="/{lang}/start"></a>{/t}
```

```yaml
agree:
  rich: true
  locales:
    ja: "利用規約に同意の上、<a>開始</a>してください"
    en: "Please <a>get started</a> after agreeing to the terms"
```

The `<a>` in the translation is a **name**, not markup: it refers to the anchor
the template wrote, so a translator can move it through the sentence and cannot
add an element, an attribute, or a script. Write the anchor empty — the text
between its tags comes from the translation. A rich-text block is legal where
children are legal, never inside an attribute value; an ordinary reference is a
string and goes anywhere an expression does.

## Routing modes

Three modes, declared per path prefix; the longest matching prefix wins, so
`header_routes = ["/api/"]` beats `path_routes = ["/"]` for `/api/…`.

| Mode | Decided by | `Vary` | Take it for |
| --- | --- | --- | --- |
| `path` | the URL prefix | nothing | public pages — two languages are two URLs, a shared cache works, and `hreflang` has something to point at |
| `cookie` | the locale cookie, then `Accept-Language` | `Cookie`, `Accept-Language` | an authenticated application, where a stored choice should outrank the browser |
| `header` | `Accept-Language` | `Accept-Language` | an API, whose client manages no cookie |

A path outside every declared prefix serves the default language with nothing in
its URL, so adding i18n to one subtree leaves the rest alone. Every response
carries `Content-Language`.

A negotiated route varies on **every** response, not only the ones that carried
the signal: language has no floor, so a reader arriving with no cookie would
otherwise fill a shared cache with an unvaried default that the next reader is
then handed.

### The root of a path-routed site

`/about` names no language, so it is negotiated and redirected to `/ja/about`
with a `302` — the target depends on who asked, and a permanent status would
cache one reader's negotiation for everyone behind the same proxy. The prefix
position is always read as a language, so `/de/about` where German is not
declared is an ordinary path rather than a broken locale.

`prefix_default = false` makes `/about` Japanese and permanently redirects
`/ja/about` to it, saving the negotiation round trip on the visit that matters
most. The default is `true` because under `false`, changing which language is
default moves every URL on the site.

## The language switcher

One call answers what the page is available in, and the same data builds the
switcher and the `hreflang` alternates, so the two cannot disagree:

```go
for _, choice := range pw.LocaleChoices(r) {
	// choice.Locale  — the locale itself
	// choice.Label   — its name in its own language, from [i18n.label]
	// choice.URL     — this same page in that language; empty where the mode has no per-locale URL
	// choice.Current — marks the one being read
}
```

Under path routing every entry carries a URL, so the control is a list of links.
Where the locale is not in the URL there is nothing to link to, and switching is
a form post to an action calling `pw.SetLocale(w, locale)` and redirecting back.
The framework owns the cookie and its validation; the markup is yours.

## Calling a message from Go

A generated message takes the locale as its first argument, so the same function
serves a handler, a batch job, a mail renderer, and a push notification. There is
no separate library mode.

```go
greeting := messages.ShopGreeting(pw.LocaleContext(r.Context()), "Ada")
```

Outside a request there is no context to read, so parse the locale from whatever
recorded it:

```go
locale, ok := pw.ParseLocale(account.Language)
if !ok {
	locale = pw.DefaultLocale()
}
return mail.Send(account.Address, messages.MailReceipt(locale, account.Name))
```

`pw.ParseLocale` reports absence rather than substituting the default, because a
stored preference that is no longer a declared language is worth knowing about.
Matching follows RFC 4647, so `ja-JP` finds `ja`. A zero `pw.Locale` is the
explicit "nothing resolved" value and never a silent stand-in for the default.
`pw.DeclaredLocales()` lists the tags. For a URL built outside a template —
a redirect target, a link in an email, a push deep link —
`pw.LocalePath(ctx, locale, path)` applies the same prefix rule the template
binding does, so no caller branches on the mode.

## Moving an existing page into the catalog

Mark the text and let the tool do the rest:

```html
<h1 i18n>Welcome back</h1>
<input placeholder="Your name" i18n="placeholder">
```

```bash
pw i18n extract
```

It proposes an ID for each string, writes the catalog entries with the source
text recorded, replaces the marked text with a reference, and adds the scope
declaration, printing everything it decided. It declines a sentence carrying
markup and says so — that shape is the rich block above, and a hole name invented
by a tool is one no translator can check.

Other subcommands: `pw i18n check` (messages nothing references, translations
that drifted from their recorded source text), `pw i18n rename <from> <to>`,
`pw i18n export <locale> [file]` and `pw i18n import <locale> <file>` for handing
work to a translator.

## Common mistakes

- A template referencing a message with no `messages <scope>` line.
- Using `{lang}` where the document language attribute wants `{langtag}`, or
  putting `{langtag}` in a link (it is never empty, so it would prefix a URL in a
  mode that has no prefix).
- Reaching for cookie mode on public pages: it gives up shared caching entirely,
  and the cost lands the wrong way round.
- Building a locale from a request value. A locale must be one you declared —
  `pw.ParseLocale` enforces it, and an arbitrary tag reaching a URL turns every
  unmatched `Accept-Language` into a distinct address at the origin.
- Expecting a cached component to be shared across languages. A component
  rendering a message keys on the language it read; one that renders none keys
  exactly as before.
- Translating API error text on the server. Problem responses already carry a
  machine-readable code, and a native client translating it itself knows its
  device language, works offline, and ships text matched to its own version.
  Translate on the server where the client cannot: mail, push, generated
  documents, operator-configured text.
